# idea-mining

문제(페인포인트)에서 출발해 아이디어를 발굴하고 `~/ideas/`에 축적·관리하는 Claude Code 스킬.

## 왜 필요한가

대화창에서 즉흥적으로 브레인스토밍을 하면 세 가지가 문제가 된다: 나온 아이디어가 대화가 끝나면 사라지고, 매번 발굴 방식이 달라 품질이 들쭉날쭉하며, 예전에 이미 떠올렸던 아이디어인지 알 수 없다. 이 스킬은 매번 같은 절차(문제 발굴 → 해법 발산 → 점수로 수렴 → 저장)를 따르고 결과를 파일로 남겨서, 다음 세션에서도 이어 쓸 수 있게 한다.

## 설치

```
/plugin marketplace add zeromountain/idea-mining
/plugin install idea-mining@my-plugins
```

설치 식별자(`@` 뒤)는 GitHub 저장소 이름(`idea-mining`)이 아니라 `.claude-plugin/marketplace.json`의 `name` 필드인 **`my-plugins`**다. 헷갈리기 쉬운 부분이라 미리 적어둔다.

## 사용법

### 발굴 모드
새 아이디어를 찾을 때. 이런 말을 하면 트리거된다:
- "사이드 프로젝트 아이템 좀 찾아줘"
- "우리 제품에 뭘 더하면 좋을지 아이디어 뽑아줘"
- "다음 분기에 뭐 하면 좋을까"

### 조회/관리 모드
새로 발굴하지 않고 기존 아이디어를 다룰 때. `~/ideas/INDEX.md`를 읽어 답한다:
- "전에 떠올린 아이디어 뭐 있었지"
- "아이디어 목록 보여줘"
- "그 아이디어 진행 중으로 바꿔줘"

### 이 스킬을 쓰지 않는 경우
만들 것이 이미 정해진 상태에서 그걸 어떻게 구현할지 설계하는 요청, 단순 네이밍, 카피 한 줄 뽑기에는 쓰지 않는다. "무엇을 할지"가 아직 정해지지 않은 단계를 위한 스킬이다.

## 발굴 워크플로

| 단계 | 내용 | 사용자 개입 |
|---|---|---|
| 0. 스코핑 | 영역·재료 소스·제약·성공 기준을 질문 | 답변 |
| 1. 문제 발굴 | 페인포인트 8~15개 도출 (누가 / 언제 / 왜 아픈가 / 지금은 어떻게 버티나 / 왜 아직 안 풀렸나) | **체크포인트 A**: 파고들 문제 1~3개 선택 |
| 2. 해법 발산 | 문제당 5~8개, 서로 다른 각도로 강제 분산. 이 단계에선 평가하지 않음 | — |
| 3. 수렴 | 루브릭으로 점수 매기고 상위안에 검증 계획을 붙임 | **체크포인트 B**: 저장할 아이디어 확정 |
| 4. 저장 | `~/ideas/`에 파일 저장 + 인덱스 갱신 | — |

"그냥 알아서 진행해"라고 하면 체크포인트를 건너뛰고 대신 어떤 가정으로 진행했는지 결과물에 남긴다.

문제 발굴 단계는 아래 4가지 재료 소스를 조합해서 쓴다:
- **웹 리서치**: 리뷰 저평점, 커뮤니티 불평 등 불만의 원문을 찾는다
- **메모/문서**: 지정한 폴더에서 반복되는 불평이나 미완 TODO를 찾는다
- **코드베이스**: TODO/FIXME, 수동 운영 스크립트 등 방치된 흔적을 찾는다
- **모델 지식**: 외부 조회 없이 진행하되, 결과물에 "미검증 가정"이라고 표시한다

## 결과물 — `~/ideas/`

```
~/ideas/
├── INDEX.md                        # 상태별로 묶인 전체 목록
├── 2026-08-05-<slug>.md            # 개별 아이디어
└── sessions/2026-08-05-<topic>.md  # 탈락한 해법까지 포함한 세션 원본
```

- 이 폴더는 저장소 밖, 홈 디렉토리에 만들어진다. 플러그인을 설치한다고 자동으로 생기지 않고 스킬을 처음 실행할 때 생성된다.
- 상태값은 `inbox`(발굴 직후) → `exploring`(검증 중) → `parked`(보류) / `building`(실행 중) / `killed`(폐기) 5가지다.
- 저장 전에 항상 `INDEX.md`를 먼저 읽어 비슷한 아이디어가 있으면 새 파일을 만들지 않고 기존 파일에 이어붙인다.
- 탈락한 해법도 `sessions/`에 남긴다 — 오늘 버린 아이디어가 나중엔 맞는 답이 되는 경우가 흔하기 때문이다.

## 스코어링 루브릭

문제 우선 접근이라 "문제 강도"에 가장 큰 가중치를 둔다. 각 1~5점:

| 항목 | 가중치 |
|---|---|
| 문제 강도 | ×2 |
| 본인 적합도 | ×1 |
| 검증 속도 | ×1 |
| 차별성 | ×1 |

총점은 만점 25점, 같은 세션 내 후보들 사이의 상대 비교용이다. 상위안에는 반드시 **가장 위험한 가정 · 최소 검증 실험(1주 안에 확인) · kill 조건**을 붙인다 — 점수만 있고 이게 없으면 아이디어가 아니라 감상이라는 게 이 스킬의 기준이다.

## 저장소 구조

```
claude-plugins/
├── .claude-plugin/marketplace.json     # 마켓플레이스 매니페스트
└── plugins/idea-mining/
    ├── .claude-plugin/plugin.json      # 플러그인 매니페스트
    └── skills/idea-mining/
        ├── SKILL.md                    # 스킬 본문 (워크플로 전체)
        └── references/
            ├── sources.md              # 재료 소스별 수집 방법
            ├── scoring.md              # 스코어링 루브릭 상세
            └── templates.md            # 아이디어 파일 / INDEX.md / 세션 로그 예시
```

스킬 내용을 직접 고치고 싶으면 `plugins/idea-mining/skills/idea-mining/`을 편집하면 된다. 저장소 구조를 바꾸거나 새 플러그인을 추가하는 방법은 [`CLAUDE.md`](CLAUDE.md)에 정리되어 있다.
