# 증거 등급 + 기존 해결책 사전 조사

## 증거 3등급

문제나 해법의 근거로 쓰는 모든 정보에 등급을 매긴다. "확인됨/추정" 2단계보다 세분화하는 이유는, 뉴스 기사를 읽고 정리한 것과 실제 사용자가 직접 한 말은 신뢰도가 다른데 둘 다 "확인됨"으로 뭉뚱그리면 나중에 구분이 안 되기 때문이다.

- **E1 (1차 증거)**: 실제 사용자의 발언 원문이나 직접 관찰. 리뷰 인용, 커뮤니티 게시글 인용, 인터뷰 발언, 코드베이스에서 직접 읽은 TODO/이슈. 인용문 + 출처 URL(또는 파일 경로) + 확인 날짜를 함께 남긴다.
- **E2 (2차 증거)**: 기사, 리포트, 통계, 남이 요약한 자료. 원문이 아니라 누군가의 해석을 거친 정보다. 출처 URL + 날짜. **출처가 그 문제를 해결하는 상품을 파는 회사(SW 벤더, 컨설팅사 등)의 콘텐츠면 `(E2, 벤더)`로 출처 성격을 함께 표기한다** — 이해관계가 있는 쪽이 문제를 부풀려 서술할 유인이 있기 때문이다. "왜 아픈가"가 벤더 자료로만 뒷받침되면 E3와 마찬가지로 신뢰도 낮음 표시를 적용한다.
- **E3 (추론)**: 외부 조회 없이 모델 지식이나 논리로 도출한 추정. 근거처럼 보이지만 검증되지 않았다는 걸 항상 명시한다.

표기 방법: 문장 앞에 `(E1)`, `(E2)`, `(E3)`를 붙인다. 여러 소스를 섞어 쓸 때 특히 중요 — 리서치 결과 문서 안에서 어디까지가 실측이고 어디부터가 추정인지 한눈에 구분되게 한다.

**규칙**: 문제 5필드 중 "왜 아픈가"의 근거가 E3뿐이면, 그 문제는 목록에서 제외하지는 않되 **"신뢰도 낮음"이라고 표시**한다. 체크포인트 A에서 사용자가 우선순위를 정할 때 이 표시를 참고할 수 있게 한다.

## 문제 공간 지도 (기존 해결책 사전 조사)

**만드는 시점은 한 번, 쓰는 시점은 세 번이다.** 예전엔 해법을 다 발산한 뒤에야 기존 해결책을 찾았는데, 그러면 5~8개를 다 만들고 나서야 전부 이미 있는 것이었다는 걸 알게 되는 낭비가 생긴다. 그래서 1단계 문제 발굴과 같은 왕복에서 지도를 만들어 재사용한다.

**만들기** (1단계, `sources.md`의 병렬 수집 지시 참고): 문제를 찾을 때 각 문제마다 이미 존재하는 대표 해결책 2~3개를 이름·URL과 함께 같이 수집한다. 판단은 아직 하지 않는다 — 목록만 만든다.

**세 번 쓰기**:
1. **체크포인트 A**: 문제 목록을 보여줄 때 각 문제에 포화도 태그(예: "경쟁 다수" / "소수" / "안 보임")를 함께 표시해, 사용자가 문제를 고르는 시점에 이미 이걸 참고할 수 있게 한다.
2. **2단계 발산 직전**: 이미 존재하는 대표 해결책들을 발산의 **제약**으로 넘긴다 ("이미 X·Y·Z 형태가 있다. 같은 형태는 내지 마라"). 정보를 뒤늦게 필터로만 쓰지 않고, 애초에 재발명 방향으로 발산되는 걸 줄이는 데 쓴다.
3. **발산 후 해법별 대조**: 나온 해법마다 지도에 있는 목록과 대조한다. 지도에 없는 새로운 형태라면 짧게 한 번 더 검색해서 확인한다 (해법마다 처음부터 다시 전체 검색을 할 필요는 없다 — 같은 문제의 해법들은 대체로 경쟁 지형을 공유한다).

빠른 모드는 지도를 만들지 않고, 체크포인트 B 직전 상위안에만 가볍게 대조한다.

## 3갈래 판정

기존 해결책이 있다고 무조건 기각하지 않는다. 경쟁자가 많다는 것 자체가 그 문제가 실재한다는 E2급 증거이기도 하다. 대조 결과를 아래 세 갈래로 판정한다:

- **재발명**: 기존 해결책과 형태·대상이 사실상 같다. 곧바로 기각하지 않는다 — 기각 전에 **세그먼트를 좁혀 차별화할 여지가 있는지 한 번 검토한다** ("이 특정 대상·상황에는 기존 해결책이 왜 안 맞는가"에 구체적으로 답할 수 있는지). 답이 나오면 아래 "세그먼트 협소화"로 재분류한다. 이 검토는 한 번으로 제한한다 — 답이 안 나오면 그때 **기각**한다.
- **세그먼트 협소화**: 기존 해결책이 있지만 특정 사용자군·상황에는 명백히 안 맞는다 ("왜 그것으로 충분하지 않은가"에 구체적으로 답할 수 있음). → **통과**시키되, 대상을 그 세그먼트로 좁혀 다시 기술하고, `scoring.md`의 차별성 점수를 **상한 3점**으로 제한한다.
- **진짜 공백**: 기존 해결책이 구조적으로 못 하는 것을 한다 (법적·기술적·비즈니스 모델상 이유로 기존 플레이어가 할 수 없는 영역). → **통과**, 차별성 만점도 가능.

"충분하지 않은 이유"를 답하지 못하면(재발명으로 판정되면) 그 해법은 통과시키지 않는다. 아무 기존 해결책도 못 찾았다면 그 자체가 흥미로운 신호일 수 있지만, 동시에 "왜 아직 아무도 안 만들었나"(도메인 파일의 필수 질문 참고)에 대한 답과 모순되지 않는지 점검한다.

**피벗 재조사**: 비평(`critique.md`) 단계에서 해법의 형태가 실질적으로 바뀌면(피벗), 그 새 형태에 대해 위 대조를 다시 한다 — 단, 해법 한 줄 요약을 다시 썼을 때 검색어 자체가 달라지는 경우에만. 전체 지도를 새로 만들 필요는 없고 검색 1~2회로 축약한다.

이 조사 결과는 저장되는 아이디어 파일에 "기존 대안" 섹션으로 남긴다(`templates.md` 참고).
