```markdown
# 소규모 세무사무소용 거래 자동분류 정확도 개선 도구

## 문제
- **누가**: 월 100건 이하 처리하는 1인·소규모 세무사무소
- **언제**: 매월 마감 시 거래 내역을 회계 SW에서 불러온 직후
- **왜 아픈가**: 잘못 분류된 항목을 하나하나 재확인하느라 건당 10~15분 추가 소요, 월 15~20시간
- **지금은 어떻게 버티나**: 엑셀에 규칙을 따로 만들어 수작업 대조
- **왜 아직 안 풀렸나**: 대형 회계 SW는 대량 고객 대상 범용 모델이라 업종별 미세조정을 안 함

(확인됨, 출처: https://example.com/review-thread) 관련 커뮤니티 스레드에서 동일 불만 다수 발견.
(추정) 소규모 사무소일수록 업종이 몰려 있어 미세조정 여지가 클 것으로 보임 — 미검증.

## 해법 (선택된 것)
기존 회계 SW에 플러그인으로 붙는, 업종별 규칙 학습형 분류 보조 도구.

## 스코어
| 항목 | 점수 |
|---|---|
| 문제 강도 (×2) | 5 |
| 본인 적합도 | 3 |
| 검증 속도 | 5 |
| 차별성 | 4 |
| **합계** | **22** |

## 검증 계획
- **가장 위험한 가정**: 세무사가 이 불편 때문에 실제로 별도 유료 도구를 도입할 의향이 있다 (지금은 그냥 참고 있을 수도 있음)
- **최소 검증 실험**: 세무사 커뮤니티에 문제 설명 + 관심도 조사 게시, 5명 인터뷰
- **kill 조건**: 인터뷰 5명 중 3명 이상이 "그 정도는 감수할 만하다"고 답하면 접는다
```

## 세션 로그 (`~/ideas/sessions/YYYY-MM-DD-<topic>.md`)

탈락한 해법까지 전부 남긴다. 오늘 버린 게 나중에 맞는 답이 되는 경우가 흔하기 때문이다.

```markdown

- 재료 소스: 웹 리서치 + 모델 지식
- 제약: 초기 예산 없음, 1인 개발
- 성공 기준: 바로 검증 시작할 것 1개

## 발굴된 문제 (전체)
1. ...
2. ...

## 발산된 해법 (선택 안 된 것 포함)
### 문제: 거래 자동분류 정확도
- 해법 A (선택됨): 플러그인형 분류 보조 도구 → `~/ideas/2026-08-05-tax-autocategorize.md`
- 해법 B (탈락, 점수 12): 완전히 새 회계 SW 자체 개발 — 진입장벽이 너무 높다고 판단
- 해법 C (탈락, 점수 9): 세무사 대상 컨설팅 서비스 — 확장성 낮음

## 저장된 아이디어
```
