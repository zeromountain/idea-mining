# 스코어링 루브릭

문제 우선 접근이므로 "문제 강도"에 가장 큰 가중치를 둔다. 아무리 기발한 해법이라도 문제 자체가 약하면 아무도 쓰지 않는다.

각 항목 1~5점, 아이디어당 4개 항목 평가:

| 항목 | 가중치 | 1점 | 3점 | 5점 |
|---|---|---|---|---|
| 문제 강도 | ×2 | 가끔 불편한 정도 | 주기적으로 시간/돈을 쓰게 만듦 | 방치하면 손실이 누적되거나 리스크가 큼 |
| 본인 적합도 | ×1 | 접근 가능한 사용자·기술·유통이 전혀 없음 | 일부 갖춰져 있으나 새로 배워야 함 | 이미 사용자/기술/유통 채널에 닿아 있음 |
| 검증 속도 | ×1 | 검증에 몇 달 이상 필요 | 1~2주 내 부분 검증 가능 | 며칠 안에 사실 여부 확인 가능 |
| 차별성 | ×1 | 기존 대체재와 거의 동일 | 일부 우위는 있으나 대체재가 쉽게 따라할 수 있음 | 기존 대체재가 구조적으로 못 하는 것을 함 |

총점 = (문제 강도 × 2) + 본인 적합도 + 검증 속도 + 차별성 (만점 25점). 절대 기준이 아니라 같은 세션에서 나온 후보들 사이의 상대 비교 용도로 쓴다.

## 상위안에 반드시 붙이는 3종

점수만 매기고 끝내면 그건 아이디어가 아니라 감상이다. 상위 3~5개에는 아래 셋을 채운다.

### 1. 가장 위험한 가정
이 해법이 성립하려면 무엇이 참이어야 하는가 중, 가장 불확실하고 가장 크게 틀릴 수 있는 것 하나를 고른다. "사람들이 이 문제를 돈 내고 해결하고 싶어 한다" 같은 막연한 것 말고, 구체적으로 좁혀서 쓴다.

**나쁜 예**: "사람들이 관심 있을 것이다"
**좋은 예**: "월 100건 이하 세무사가 기존 툴의 자동 분류 정확도(약 80%)에 실제로 불만을 느껴 대안을 찾고 있다"

### 2. 최소 검증 실험
1주 안에, 최소한의 비용으로 위 가정을 확인할 방법. 제품을 만들지 않고 확인하는 게 원칙이다.

예: 랜딩페이지 + 광고로 신청률 측정, 잠재 사용자 5명 인터뷰, 기존 대체재 사용자 커뮤니티에 직접 질문 올리기, 수동으로 서비스를 흉내내서(오즈의 마법사) 반응 보기.

### 3. Kill 조건
무엇을 확인하면 이 아이디어를 접을지 미리 정한다. 나중에 애착이 생긴 뒤에 정하면 객관적으로 판단하기 어렵기 때문에 지금 정해둔다.

예: "인터뷰 5명 중 3명 이상이 '지금 방식도 괜찮다'고 하면 접는다", "랜딩페이지 전환율이 3% 미만이면 접는다".
